# DA-32 Tray-Transfer Task Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A G1 tray-transfer task (two tables, tray with two handles and six loose parts, target zone) that runs in SIMPLE with `sim_mode=mujoco`, with tested randomization, step predicates and success check (milestones M0 1/11 and M1 4/11).

**Architecture:** Pure-Python logic (config, scene geometry, randomization, predicates) lives in `flywheel_simple.tray` with no `simple` or `mujoco` import, so it runs in workspace CI. Two thin glue modules import `mujoco` (tray MJCF builder) and `simple` (task class, registration); their tests carry the `sim` marker and run only in the SIMPLE environment. The task is registered from our package at import time; a small runner imports it and then calls SIMPLE's own CLIs, so SIMPLE is not forked.

**Tech Stack:** Python 3.10 (SIMPLE env) and the workspace Python (pure logic); MuJoCo 3.3.6 `MjSpec`; SIMPLE at commit `6d10628794d9c7de4596b4f2afb2c054a637c2bc`; gymnasium registration; numpy; pytest.

**Spec:** [docs/superpowers/specs/2026-10-28-tray-transfer-he-design.md](../specs/2026-10-28-tray-transfer-he-design.md) and story [DA-32](../../product/stories/DA-32-task-be-khay.md).

## Review Focus

1. A level-2 seed places the tray or target zone partly over a table edge → sampler must reject and resample; test in Task 5.
2. Parts spawned interpenetrating the tray dividers explode at t = 0 → static-scene test in Task 3 checks the first 0.1 s too.
3. Tray yaw near ±π wraps and fails the 10° tolerance although the tray is placed correctly → angle-difference test in Task 6.
4. Success flickers when the tray bounces once after release → `T_stable` must be continuous; test in Task 6.
5. G1 spawn pose intersects table A at level 2 → robot spawn clearance test in Task 5.
